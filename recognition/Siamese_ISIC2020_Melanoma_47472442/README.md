# ISIC 2020 Melanoma Triage with Siamese Metric Learning

This COMP3710 research project compares a direct convolutional neural-network
baseline with a Siamese metric-learning model for melanoma triage from dermoscopic
images. The code is organised for a reproducible local experiment; final model
results are generated by a completed run and are not claimed in this repository.

## Problem and Algorithm

The task is binary classification of a dermoscopic image as benign (`0`) or
melanoma (`1`). A direct CNN maps an RGB image to two logits. The training driver
uses a weighted cross-entropy loss so the rare melanoma class contributes to
optimisation.

The Siamese alternative maps each RGB image through a shared CNN encoder into a
unit-length embedding. Contrastive loss moves embeddings from same-class training
pairs together and separates different-class pairs. At prediction time, the model
scores a query by comparing its embedding with a fixed reference gallery drawn
only from training patients.

## How the Siamese Model Works

Both branches of the Siamese network share exactly the same encoder weights. A
pair of images therefore becomes two points in one embedding space. The loss is
small for pairs with the same label when their embeddings are close, and penalises
different-label pairs that remain within the configured margin.

The saved experiment checkpoint records the selected gallery image IDs and its
neighbour count. `predict.py` rebuilds that exact gallery instead of sampling a
new one. It uses the difference between benign and melanoma nearest-reference
distances as a melanoma ranking score. This score is not presented as a calibrated
probability.

## Feasibility Review

The one-page feasibility review defined the following engineering question: can
Siamese similarity scores expose ambiguous or incorrect melanoma-triage decisions
better than the direct CNN at an acceptable local computational cost?

Preliminary data audit evidence from that review identifies 33,126 labelled ISIC
2020 images from 2,056 patients, including 584 melanoma images (1.76%). The audit
also found that all 425 published duplicate pairs share a patient ID and label.
These observations motivate patient-level splitting and a training-only reference
gallery. They are feasibility evidence, not model-performance results.

The JPEG archive is about 23 GB. The planned local pilot uses the available Apple
MPS backend with batch size 16 and a small gallery first, reducing batch size,
image resolution, or encoder width only if resource measurements require it. The
comparative study must report melanoma recall, false-positive rate, referral
fraction, parameter count, memory, and per-image latency before making an
engineering recommendation.

## Installation and Reproducibility

Create an environment with the exact versions captured from the local development
environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r recognition/Siamese_ISIC2020_Melanoma/requirements.txt
```

Run every command from the repository root. The default `--device auto` chooses
CUDA when available, then Apple MPS, then CPU. Use an explicit `--device mps` or
`--device cpu` only when a particular device is required for an experiment.

## Data Preparation and Patient-Level Split

Download and extract the ISIC 2020 training JPEG archive and place the images and
`ISIC_2020_Training_GroundTruth_v2.csv` beneath the repository-local `data/`
directory. The standard layout is:

```text
data/
├── ISIC_2020_Training_GroundTruth_v2.csv
└── train/
    └── ISIC_*.jpg
```

`dataset.py` loads images lazily as 224 by 224 RGB tensors. Horizontal and
vertical flips apply only to training images; validation, test, gallery, and
prediction views are deterministic. The first training run writes a patient-level
manifest to `data/splits/isic_seed42.json`. Later baseline and Siamese runs verify
and reuse that manifest, preventing a patient from appearing in more than one
partition.

## Training

Run the direct CNN baseline:

```bash
python -m recognition.Siamese_ISIC2020_Melanoma.train \
  --config recognition/Siamese_ISIC2020_Melanoma/configs/baseline.yaml
```

Run the Siamese experiment on the same persisted split:

```bash
python -m recognition.Siamese_ISIC2020_Melanoma.train \
  --config recognition/Siamese_ISIC2020_Melanoma/configs/siamese.yaml
```

Each run saves `checkpoint.pt`, `metrics.json`, `test_predictions.csv`, and
`training.svg` under `data/runs/<run-name>/`. The decision threshold and referral
band are selected from validation data, then frozen before held-out test scoring.

## Prediction and Visual Outputs

Reload a completed baseline run without retraining:

```bash
python -m recognition.Siamese_ISIC2020_Melanoma.predict \
  --checkpoint data/runs/baseline_seed42/checkpoint.pt \
  --metrics data/runs/baseline_seed42/metrics.json \
  --output-dir data/runs/baseline_seed42/predictions
```

The prediction command reconstructs the saved test partition, applies the
validation-derived decision rule, prints and saves the held-out prediction rows,
and creates `test_score_distribution.svg` plus `failure_cases.svg`. SVG files
under `data/` are run artifacts. Copy only selected final figures into the tracked
`figures/` directory when writing the assessment report.

## Baseline and Siamese Investigation

The two experiments share image preprocessing, seed, patient manifest, validation
and test partitions, and the same reporting pipeline. The baseline supplies a
direct melanoma probability. The Siamese model supplies a gallery-based ranking
score and must retain its exact training-only gallery in the checkpoint.

Compare melanoma PR-AUC, AUROC, macro-F1, per-class precision and recall, and the
validation-selected operating point. Report the measured values from each saved
run; no comparative result has been recorded here.

## Resource Profile

`train.py` records model parameter count, fixed validation-batch forward latency,
and available accelerator-memory information in `metrics.json`. Record the device,
batch size, image size, timing scope, and measured values for both models in the
assessment report. No resource values are claimed before a completed run.

## Failure-Case Autopsies

`predict.py` creates a labelled SVG montage of up to five held-out review cases.
It includes a false negative and false positive when available, then fills the
remaining places with cases closest to the frozen threshold. Discuss the image
appearance, model score, decision, relevant gallery evidence, and plausible
limitation for each selected case after inspecting an actual run.

## Engineering Recommendation

Choose between the baseline and Siamese approach only after comparing held-out
performance, referral behaviour, failure cases, and resource measurements. If the
Siamese model does not show a reliable triage benefit, the project should report
that result and prefer the simpler validation-calibrated CNN with human review.
